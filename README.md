# DecodeLabs — AI Track — Project 2: Data Classification Using AI

Industrial Training Kit | Batch 2026 | Powered by DecodeLabs

Predicts `OrderStatus` (Cancelled / Delivered / Pending / Returned / Shipped)
for an e-commerce order using a K-Nearest Neighbors classifier, following
the **Input → Process → Output** framework from the Project 2 briefing.

**Dataset used:** `Dataset_for_Data_Analytics.xlsx` (kept under its
original filename, exactly as provided) — 1200 rows of real order
records. Nothing else was substituted in.

## How to run

You need two terminals — one for the backend API, one for the frontend.

### 1. Backend (API server)

```bash
cd backend
pip install -r requirements.txt
uvicorn server:app --reload --port 8000
```

This starts the API at `http://localhost:8000`. Verify it's up:
```bash
curl http://localhost:8000/api/health
```

### 2. Frontend (React dashboard)

```bash
cd frontend
npm install
npm run dev
```

Open the URL it prints (default `http://localhost:5173`). The frontend
talks to `http://localhost:8000` by default — copy `.env.example` to
`.env` and edit `VITE_API_BASE` if your backend runs elsewhere.

### What you'll see
- **Overview** — dataset size, OrderStatus distribution, a sample of rows
- **Train & evaluate** — sliders for K and test-set size; live accuracy,
  weighted F1, and a confusion matrix heatmap after training
- **Predict** — fill in an order's details (product, payment method,
  coupon, referral source, quantity/price) and get a live predicted
  `OrderStatus` with per-class probabilities

### Alternative: command line only (no frontend)
```bash
cd backend
pip install -r requirements.txt
python main.py            # or: python main.py --k 9
python -m unittest discover -s tests -v
```

## Results — read this before assuming higher is always better

The model scores **~17-18% accuracy**, at or below a random-guess
baseline (~20-25%, since there are 5 roughly equal classes). This means
the available order details carry **little to no predictive signal**
for `OrderStatus` in this dataset — verified against a random-guess
baseline and across a sweep of K values (see `backend/docs/report.md`
for the full breakdown). It's reported honestly here — including live
in the frontend's "Train & evaluate" tab — rather than tuned to look
better than it is, in the spirit of the briefing's own "Output
Validation / Accuracy Mirage" lesson.
